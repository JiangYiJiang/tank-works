### 1.9 经济闭环 M1 ✅

- 招标：每个时代三档标（4 / 8 / 16 台），门槛 = 同期参照车四维 × 70%、总分 × 55%
- 竞品：每份标带一个竞品（名字 / 总分 / 报价），按种子确定性生成
- 接单：原价、压价 5%（要求降 5% 的竞品分）、贿赂（付 8% 合同额，跳过竞品分）
- 信誉 0–100：报价 ×0.90–1.10；按期 +2，逾期 −5，贿赂被查 −15
- 国家/市场：开局选国家，开工后国籍锁定；当前**阵营限制暂关**，所有已进入市场的国家都能成为客户，只排除本国（苏联 1922、新中国 1949 才进入市场）
- 竞品逐年成长：竞品总分 = 参照车总分 ×（公司 skill + 年份成长 + 抖动），上限 1.02；换届时发「竞品动态」新车
- 标上显示客户现役型号与需求台数；自动暂停覆盖订单完成、科技完成、现金告急、交期临近、时代/快讯
- 年度审计：每笔未消账贿赂 +10% 被抓概率（上限 60%），罚款 10% 现金 + 信誉 −15
- 排产：200 人 × 1 班，每天扣工资、出车、交付、回款；学习曲线照旧
- 逾期单价 ×70%；现金 < 0 先自动透支，授信用满才破产；交完自动重新招标
- 贷款：授信 =（100 万 + 信誉×2 万）× 年份通胀；年化 8% 按日滚入本金；可借 / 可还
- 多产线：最多 3 条，共享仓库与成品池；加线 30 万、扩编 8 万/100 人、加班 12 万/班
- 材料价格：按年份漂移 + 周期 + 确定性噪声，落在 0.82–1.25；接单时锁价
- 经济尺度 v1：8 个时代毛利 15–25%、单台 3.1–12.8 天、4 台小单利润够付首项技术；`npm run scale` 锁四条线
- 累计账：回款、材料、工资、研发、贿赂、罚款、利息、订单数、出车数；关厂报告直接读它
- 产品按年代解锁（当前年份 + 2 年），换产品在下次接单时换型、熟练度 ×0.35

**验证**：`npm run economy` → **96 项断言**；`npm run smoke:game` → **104 项断言**

### 1.10 设计局 → 主循环 ✅

- 设计局右上角「采用此设计」：把六槽位设计 + 型号名写进 `localStorage`（`tank-works.design.v1`）

**验证**：`npm run smoke:tank` + `smoke:game` + `economy` + `research`（设计年代、超前拦截、科技过滤、导入后存档）

## 附录 J：fn 收尾 / 主动防御 / 多合同评估（2026-11-03）

**fn 收尾**：

- `density`：长杆 / 脱壳弹的弹芯质量按 `density/15` 放大（只影响穿深质量，不影响初速），18/19 对应 +20% / +27%

- 设计局物理量增加「主动防御 有/无」；1991 年前可造，但会占掉辅助槽

**多合同评估**：

| 方案 | 改动 | 风险 |
|---|---|---|
| A. 每线独立合同 | `contracts[]` + 线-合同绑定 + 分线交付/回款 | 合同状态、UI、存档全要重做；平衡难度大 |
| B. 单合同多线 | 当前做法 | 产能扩张有意义，但没有「同时接两单」的调度 |
| C. 多合同共享产线 | 一个合同池，产线按优先级排产 | 最灵活，也最难解释/调试 |

**决定：暂不做多合同**（选 B）。当前一局的核心决策已经够多（国家/产品/研发/接单方式/产能），多合同会先把 UI 与存档复杂度翻倍，而收益主要是后期。等核心循环稳定后再评估 A。

## 附录 P：Windows 桌面版（2026-11-04）

**需求**：把游戏做成 `.exe` 启动的桌面游戏；主菜单设置可选全屏 / 窗口化全屏幕 / 窗口，并设置主音量、音乐、音效（音频播放后续再做）。

**架构**：不改模拟与 UI，只加 Electron 壳和平台设置层。

- `desktop/main.ts`：自定义协议 `app://tankworks/`、单实例锁、`window-state.json`（模式 + bounds）、三显示模式、模式切换重建窗口、IPC、外链拦截
- `desktop/preload.ts`：contextBridge 暴露 `window.tankWorksDesktop`，不暴露 `ipcRenderer`
- `desktop/build.mjs`：esbuild 打 CJS main/preload（ESM main 会报 electron 无 `BrowserWindow` 命名导出）
- `desktop/pack.mjs` + `electron-builder.yml`：electron-builder，NSIS 安装包 + portable exe，输出 `release/`
- `src/platform/settings.ts`：`tank-works.settings.v1` 统一设置；兼容旧版只有 `reduceMotion`
- `src/platform/desktop.ts`：桌面桥接口与全局类型
- `src/tank/menu-main.ts` / `menu.css`：设置覆盖层加三模式按钮、三条音量滑条；桌面版退出直接 `quit()`；浏览器禁用模式按钮
- `build/icon.ico` / `build/icon.png`：深色圆角底 + 两块琥珀方块

**坑**：

- Electron 二进制默认从 GitHub 下载会被重置；用 `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/` 重跑 `node node_modules/electron/install.js`
- 本机有 `ELECTRON_RUN_AS_NODE=1`，直接跑 electron.exe 会当 Node 执行；启动前删除该环境变量
- `fullscreen: true` 在构造参数里不生效，改到 `ready-to-show` 后 `setFullScreen(true)`
- 写 `window-state.json` 的 UTF-8 BOM 会让 `JSON.parse` 失败并回退窗口模式；读时 `replace(/^\uFEFF/, '')`
- 模式切换只能重建窗口（Electron 不能运行时改 `frame`）；因此设置只在主菜单提供

**验证**：`npm run check` 612；`npm run build`；`release/win-unpacked/Tank Works.exe` 冒烟；window 1280×800 可缩放、borderless 1920×1035、fullscreen `isFullScreen=true`；打包产物 `Tank Works-0.2.0-x64.exe` 与 `Tank Works-0.2.0-portable.exe`。

**后续**：音频资源与播放逻辑（P1-19）；文件系统存档（P3-24）；代码签名；自动更新；模式内实时切换（自定义无边框标题栏）。
